# Prepared knowledge and shared groups

Direction agreed on 2026-10-02. Build through one verified example
area, stopping before bulk Luna authoring. Preserve the original shared $5 test
ledger, including prior spending and unknown holds.

World, zone, location, NPC and quest facts are authored offline with sources and
an explicit era. A bounded resolver selects applicable records using native IDs
and current quest state; it never researches or regenerates a biography during
dialogue. Existing identities and owner corrections survive catalogue updates.
Quest overlays describe the speaker's interaction with the current player, not
global world progress. Canon and authored personality remain distinguishable.

Watches, native player guilds and configured NPC organisations use the same
attributed report mechanism. Membership grants current access, not personal
experience. Reports retain evidence, expire from retrieval, deduplicate shared
sources, and respect corrections. Private conversations cannot become shared
reports merely because the speaker belongs to a group. Native guild membership
and language comprehension remain server decisions.

First scope: explicit group membership, guild conversation, compact knowledge,
quest overlays and bounded reports. Autonomous recruitment, guild banking,
global rumor diffusion and bulk content research are outside this change.

Acceptance checks:
1. Move between Northshire locations: local context changes; identity persists.
2. Accept, fulfill and turn in a quest: context follows the correct native stage
   for this player; another player does not inherit that progress.
3. Share a watch/guild report: eligible members see attributed information;
   unrelated groups and departed members receive no new reports.
4. Repeat, revise and age reports: duplicates stay bounded; stale or invalidated
   evidence disappears from retrieval without destroying source history.
5. Cross a language boundary: unintelligible words do not become memories;
   selected knowledge fits its explicit byte budget without truncating facts.

Validation uses the existing isolated stack and synthetic/recorded transport
first, followed by a small paid sample only if allowance remains. Human playtest
services, live histories and unrelated in-progress edits are not deployment
targets. No commits or publication are authorised.
